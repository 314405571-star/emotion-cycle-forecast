# 情绪周期算法总结：从四个宽度指标到明日预判

> 对应代码：`src/emotioncycle/`（核心为纯标准库，不联网、不依赖聚宽）。
> 原始实现：`legacy/v2.4.py`，逐字保留。

---

## 0. 一句话

每天收盘后，用 800 只股票的涨跌、涨停、封板、大跌四个比例，
算出 0–100 的**情绪指数**，再用一台七状态的机器把它归入
**冰点 / 修复 / 上升 / 高潮 / 分歧 / 退潮 / 正常**之一，映射成一个仓位上限。
最后，用最近 7 天的斜率去**预判明天**属于哪个阶段。

前两步是测量，第三步是预测。测量可以检验，预测通常没人检验——这个仓库把检验补上了。

---

## 1. 四个宽度指标

从全市场随机抽 800 只（按交易日做种子，同一天内可复现）：

| 指标 | 定义 | 直觉 |
|---|---|---|
| `up_ratio` | 收涨家数 / 总数 | 今天有多少票是红的 |
| `limit_ratio` | 涨停家数 / 总数 | 赚钱效应的顶端 |
| `seal_rate` | 涨停家数 / 摸过涨停的家数 | **封住了多少**，情绪最灵敏的一格 |
| `big_loss_ratio` | 跌幅 ≥ 7% 的家数 / 总数 | 亏钱效应的强度 |

另外两个不进入指数、只用于扩散度：`strong`（涨幅 > 5%）与 `mid`（2%–5%）。

**封板率是这套模型里最有信息量的指标。** 涨停家数只说明"有人冲"，封板率说明
"冲上去之后守不守得住"——同一天 40 家涨停、封板率 50% 与 20 家涨停、封板率 90%，
是两种完全不同的市场。

---

## 2. 情绪指数

四个子分数，各自压到 0–100：

```
limit_score = min(100, limit_ratio × 1000)          10% 的票涨停 = 满分
up_score    = clip((up_ratio − 0.30) / 0.40 × 100)  30% 上涨 = 0，70% 上涨 = 100
seal_score  = seal_rate × 100                       封板率即分数
loss_score  = clip(1 − big_loss_ratio / 0.05) × 100  5% 的票跌 7% = 0 分
```

加权：

```
emotion = 0.35·limit + 0.25·up + 0.25·seal + 0.15·loss
```

几点说明：

- `limit_score` 用的是 ×1000，也就是 10% 涨停率封顶。这是历史上极端高潮日的量级。
- `up_score` 的 30%–70% 映射把"一半涨一半跌"放在 50 分附近，高于 30% 才开始计分。
- `loss_score` 是**反向**的：大跌越多分越低。原实现用 `1 − 家数/40`，
  这里改成**比例**——见第 7 节。

### 2.1 盘中置信度与夹逼

盘中每隔一段时间更新时，早上的数据只覆盖了半天的成交，读数不稳，所以：

```
blended = yesterday × (1 − c) + raw × c
emotion = clamp(yesterday, blended, ±15)
```

`c` 是时间置信度：09:30 为 0.30，10:30 为 0.70，14:30 为 0.95，收盘 0.98。
再加一道 ±15 的日变动上限，防止一根异常数据把状态机打飞。

## 3. 七阶段状态机

```
        冰点 ──► 修复 ──► 上升 ──► 高潮 ──► 分歧 ──► 退潮 ──┐
          ▲                                                  │
          └──────────────────────────────────────────────────┘
                        （正常：循环之外的中性态）
```

判定顺序（先绝对条件，后相对变化）：

1. **高潮**：`limit_ratio > 4%` 且 `seal_rate > 70%` 且 `up_ratio > 60%`
2. **冰点**：`up_ratio < 25%` 且 `big_loss_ratio > 3.5%`
3. **分歧**：昨日是高潮或上升，且情绪比昨日跌 5 点以上
4. **修复**：昨日是冰点/分歧/退潮，且（单日涨 5 点 **或** 三日涨 5 点）且 `up_ratio > 40%`
5. **退潮**：情绪比昨日跌 3 点以上，且仍在 30 以上
6. **上升**：昨日是修复或上升，且情绪比昨日涨 3 点以上
7. 否则维持昨日阶段

### 3.1 滞回

第 4–6 条都带 ±3 的阈值，这是**滞回**：没有 3 点以上的变化就不换状态，
避免在阈值附近来回抖。代价是状态会滞后一天左右——这也是为什么
"推断阶段"与生成器的"真实阶段"只能对上六成，而不是百分百。

### 3.2 仓位映射

| 阶段 | 冰点 | 修复 | 上升 | 高潮 | 分歧 | 退潮 | 正常 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 仓位上限 | 20% | 60% | 80% | 40% | 30% | 10% | 50% |

注意高潮期的仓位**低于**上升期：这是"在别人贪婪时减仓"的直接编码。

---

## 4. 转折点与提前信号

三个条件都成立时给出转折信号（需要昨日的数据）：

| 信号 | 条件 | 含义 |
|---|---|---|
| 分歧转一致 | 昨日分歧 → 今日修复/上升/高潮，且 `limit_ratio > 1.2×昨日`、`seal_rate > 1.1×昨日` | 买入 |
| 冰点转修复 | 昨日冰点 → 今日修复，且 `up_ratio > 40%` | 左侧布局 |

**提前信号**用扩散度（`mid / strong × 100`）：

- 高潮期扩散度 < 35：强势股在收缩，提前减仓；
- 冰点期扩散度 > 55：赚钱效应在扩散，提前关注。

扩散度衡量的是"涨幅 2–5% 的票相对 5% 以上的票有多少"——
高潮期这个比例骤降，说明只有少数龙头在涨，其余已经掉队。

## 5. 明日预判

输入：当前阶段、最近 7 日情绪的斜率（最小二乘）、最近一日变化。输出：主预判、备选、置信度。

规则表（节选）：

| 当前 | 条件 | 主预判 | 置信度 |
|---|---|---|---:|
| 冰点 | 斜率 > 2 或 单日 > 5 | 修复 | 0.70 |
| 冰点 | 斜率 > 0 | 修复 | 0.55 |
| 修复 | 斜率 > 3 或 单日 > 8 | 上升 | 0.70 |
| 上升 | 斜率 > 5 或 单日 > 10 | 高潮 | 0.70 |
| 高潮 | 斜率 < −3 或 单日 < −5 | 分歧 | 0.70 |
| 分歧 | 斜率 > 2 或 单日 > 5 | 修复 | 0.70 |
| 退潮 | 斜率 > 1 或 单日 > 2 | 冰点 | 0.60 |

这些置信度是**写死的**。原始实现里没有一行代码检验过它们，也没有任何东西
说明 0.70 和 0.65 的差别从哪来。

### 5.1 评估器（本仓库新增）

```python
from src.emotioncycle.forecast import evaluate
result = evaluate(emotions, phases)
result.accuracy            # 整体命中率
result.baseline            # 「明天 = 今天」的持久性基线
result.transition_accuracy # 只在阶段真的切换的那天
result.by_confidence       # 声明的置信度 → 实际命中率（校准）
```

三个指标缺一不可：

- **整体命中率**会被"阶段很少变"稀释，所以一定要和持久性基线比；
- **转移日命中率**是唯一能证明预测有价值的地方——持久性在转移日的命中率恒为 0；
- **校准**检验置信度是不是在说实话。

## 6. 合成装置：我们怎么知道它有没有用

`examples/demo_cycle.py` 生成一个**隐藏阶段**的合成市场：阶段按马尔可夫链演化
（停留 84%，前进 11.5%，跳一格 4.5%），每天按该阶段的分布生成 800 只股票的涨跌，
再让模型只看这些涨跌去反推阶段。

实测（260 个交易日，固定种子）：

| 指标 | 结果 |
|---|---|
| 推断阶段 = 隐藏阶段 | **61.5%**（随机猜 14.3%，多数类基线 28.5%） |
| 次日预判（整体） | 55.3%（持久性基线 72.0%） |
| 次日预判（转移日，n=72） | **30.6%**（持久性 0%） |
| 校准：声明 0.70 的分支 | 实际 32.7% |
| 校准：声明 0.60 的分支 | 实际 78.9% |

三句话读完：

1. **状态机确实在读周期**——六成的日子能对上一个自己看不到的隐藏阶段，
   是随机猜测的四倍多。
2. **预判整体上打不过「明天和今天一样」**——因为阶段大多数时候不变。
3. **但在真正要紧的那 72 天里，规则表抓到了三成**，而持久性一个都抓不到。
   同时它的置信度是失准的：声明 0.70 的分支只兑现了 33%。

最后一条最重要，也最容易被忽略：**一个预判模块的价值不在于它说了什么，
而在于你有没有一个记分牌去核对它。**

## 7. 缺陷清单

| # | 缺陷 | 后果 | 修复 | 测试 |
|---|---|---|---|---|
| 1 | `big_loss_score = 1 − 家数/40` | 分母是写死的家数。样本从 800 改到 400，同一个市场读出来的亏钱效应翻倍 | 用比例：`1 − big_loss_ratio / 5%` | `test_big_loss_score_scales_with_sample_size` |
| 2 | 没有股票摸涨停时 `seal_rate = 0.5` | 一个死掉的市场被读成"封板率中性"，情绪被抬高 | 返回 `None`，在指数里显式取中性值 | `test_seal_rate_is_none_when_nothing_touched` |
| 3 | 置信度 < 0.60 才混合，一旦 ≥ 0.60 直接用原始值 | 0.599 → 0.600 之间输出跳变 0.41×(raw−昨收)，最高 16 分 | 始终按置信度线性混合 | `test_blend_is_continuous_at_the_notebook_gate` |
| 4 | 高潮后跌 4 点 → 直接判"退潮" | 跳过"分歧"，周期顺序被破坏 | 高潮只能先到分歧 | `test_climax_never_jumps_straight_to_fall` |
| 5 | 修复要求单日涨 5 点 | 每天涨 3 点的温和修复永远走不出退潮，最后直接跳"上升" | 加上三日的累计变化 | `test_gradual_recovery_reaches_repair` |
| 6 | 分歧只能从"高潮"进入 | 只要峰值晚识别一天，整个分歧段全部丢失 | 上升也可以转入分歧 | `test_divergence_can_follow_rise` |
| 7 | 预判的置信度是断言，没有评估 | 7 个分支的 0.50–0.70 从未被核对 | `evaluate()`：整体 / 转移日 / 校准 | `test_evaluate_matches_predict_step_by_step` |
| 8 | 扩散度历史在每次 `update()` 追加 | 盘中每 5 分钟调一次，一天记 48 条"日"数据 | 每个交易日只允许一次更新 | `test_one_update_per_session` |

另外：`random.seed(date)` 重置的是**全局**随机数发生器，会悄悄改变进程里
其它模块的抽样；样本先抽再过滤，停牌股被逐个丢弃，导致"800 只"其实不足 800；
"正常"阶段在状态机里几乎无法进入（两个绝对条件之外，其余全是相对变化）。

| `max_daily_change` | 15 | 单日情绪变动上限 | 越低越平滑 |

## 9. 局限

1. **抽样误差。** 800 只里，涨停家数的比例标准误约 0.3 个百分点；
   封板率只由当天摸板的二三十只决定，噪声更大。情绪指数的有效精度大约 ±3 分。
2. **状态机的阈值是经验值。** ±3、±5、4%、70%、60% 都没有经过拟合，
   换一个市场（港股、美股）全部要重设。
3. **推断滞后一天。** 滞回是优点也是缺点：它防抖，也让你永远晚一天。
4. **预判没有跨市场验证。** 本仓库的 55% 与 30% 来自合成数据，
   真实历史需要接入聚宽自己跑 `evaluate()`。
5. **仓位表是主观的。** 它编码的是"高潮减仓"这一条经验，不是优化结果。
6. **没有交易成本、没有执行假设。** 仓位上限不是收益，甚至不是仓位。
7. **合成装置不等于回测。** 隐藏阶段由生成器定义，六成的一致率说明
   "规则能捞回一个已知的周期"，不说明"A 股有这样一个周期"。
