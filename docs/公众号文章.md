# 明日预判：55%，打不过"什么都不做"的 72%

> 一份流传很广的情绪周期模块（v2.4），每天收盘后告诉你：现在是什么阶段、
> 该留多少仓位、**明天大概率会怎样**。我把它的预测接上了一个记分牌。
> 结果不太好看，但比看好更有用。

---

## 一、它本来在做什么

模块每天做三件事：

**第一，读四个宽度指标。** 从 800 只股票里算：

- 上涨比例
- 涨停比例
- **封板率**（封住的 / 摸过板的）
- 大跌比例（跌 7% 以上）

**第二，合成一个 0–100 的情绪指数**，再把它归进七个阶段之一：

```
冰点 → 修复 → 上升 → 高潮 → 分歧 → 退潮 → 冰点
```

阶段直接映射成仓位上限：

| 冰点 | 修复 | 上升 | 高潮 | 分歧 | 退潮 |
|---|---:|---:|---:|---:|---:|
| 20% | 60% | 80% | **40%** | 30% | 10% |

注意高潮期是 40%——比上升期还低。这是"在别人贪婪时减仓"的直接编码。

**第三，预判明天。** 用最近 7 天的斜率，对照一张写死的规则表：

| 当前阶段 | 条件 | 主预判 | 置信度 |
|---|---|---|---:|
| 冰点 | 斜率 > 2 | 修复 | 0.70 |
| 上升 | 斜率 > 5 | 高潮 | 0.70 |
| 高潮 | 斜率 < −3 | 分歧 | 0.70 |
| 退潮 | 斜率 > 1 | 冰点 | 0.60 |

每一条都带着一个置信度。**问题是，这些置信度没有任何东西检验过。**

## 二、三个不会报错的 bug

**1. 亏钱效应的分母是写死的家数。**

```python
big_loss_score = max(0, 1 - big_loss_count / 40)
```

分母是 40 只。样本 800 只时，40 只正好是 5%。可一旦你把采样改成 400 只，
同一个市场、同样的跌幅占比，分数直接减半。

这不是参数问题，是**单位问题**：分子是家数，分母是常数，结果没有意义。

**2. 没人摸涨停时，封板率是 0.5。**

```python
seal_rate = limit_up_count / hit_limit_count if hit_limit_count > 0 else 0.5
```

一个连涨停都不敢摸的市场，被封板率打了 50 分——**死掉的市场被读成了中性**。
它该是"无法测量"，而不是"50 分"。

**3. 状态机会跳级。**

高潮期的判定是"跌 5 点转分歧"，退潮的判定是"跌 3 点转退潮"。
于是高潮后跌 4 点：分歧不触发，退潮触发了。**周期从高潮一步跳到退潮，跳过了分歧。**

同类问题还有一个：修复要求**单日**涨 5 点。一个每天温和涨 3 点的市场，
永远走不出退潮，最后直接跳进"上升"——中间的修复段整段丢失。

我在合成数据上跑，修复段被漏掉了一半。

## 三、给预测装一个记分牌

这是这个仓库真正想做的事。

预测最容易被糊弄的地方是：**你永远只记得它说对的那些**。
所以我把评估拆成三个指标，缺一不可：

### 1. 整体命中率——先和"什么都不做"比

```
规则表      55.3%
持久性基线  72.0%      ← 也就是"明天和今天一样"
```

持久性赢了 17 个百分点。

原因很简单：阶段大多数时候不变。一个每天都在喊"明天要变"的模型，
命中率当然不如一个只会说"不变"的傻瓜。

**所以单独看"整体命中率"是没有意义的。** 任何预测模块的宣传材料里，
如果只有这一个数字，基本可以不用看了。

### 2. 转移日命中率——真正值钱的地方

把"阶段真的切换了"的那天单独拿出来（这次是 72 天）：

```
规则表      30.6%
持久性       0%        ← 构造使然，它永远猜不到转折
```

**这才是预判的价值所在。** 它整体上打不过持久性，但在真正要紧的那 72 天里，
抓到了三成——而"不变"一个都抓不到。

一个交易系统需要的不是"今天和昨天一样"的确认，而是转折点的提示。
三成的转折命中率不高，但和零比，是另一回事。

### 3. 校准——置信度是不是在说实话

规则表给每个分支标了置信度。把它们分桶，看实际兑现了多少：

| 它说 | 实际发生 | 样本 |
|---|---:|---:|
| 50% | 66.7% | 15 |
| 55% | 5.6% | 36 |
| 60% | 78.9% | 128 |
| 65% | 47.8% | 23 |
| **70%** | **32.7%** | 55 |

**它最自信的那一档（0.70），实际只有三成兑现。** 而且整张表根本不单调。

这不是"模型差"，是"模型从来没有被检查过"。一个写死在代码里的 0.70，
和抛硬币时你心里的那个 0.70，是一回事。

每天生成 800 只股票，模型只看得到涨跌。五张图全部由
`python examples/demo_cycle.py` 生成。

**第一张：一条线，一个周期。**
上面两条细带分别是"隐藏阶段"和"模型推断的阶段"，下面是情绪指数和仓位上限。
对得上的比例是 **61.5%**——随机猜七个阶段是 14.3%，这是四倍多。

**第二张：四个数字，一个指数。**

能看出一件事：**封板率领先于情绪指数**——它在情绪见顶之前就开始掉。

**第三张：周期图。**
七个阶段围成一圈，箭头的粗细是转移次数，圈外的圆环是"原地不动"的天数。

每个点是一个分支，横轴是它声称的置信度，纵轴是实际兑现率。

## 五、为什么值得一个 star

因为这个仓库做了一件大多数量化代码不做的事：**给自己打分。**

- **核心是纯标准库**。`src/emotioncycle/` 不 import 聚宽、不联网，
  一条 800 只股票的宽度可以用手写的几个 `StockDay` 复现。
- **28 个测试，每个 bug 一个名字**：
  `test_big_loss_score_scales_with_sample_size`、
  `test_climax_never_jumps_straight_to_fall`、
  `test_evaluate_matches_predict_step_by_step`……
- **评估器是一等公民**：整体、转移日、校准，三个维度都能一行调出来。
- **五张图**，深色/浅色统一，全部来自离线脚本。
- **接上聚宽只要十几行**：`Monitor.update(day, breadth)`。

```bash
git clone https://github.com/314405571-star/emotion-cycle-forecast
cd emotion-cycle-forecast
python examples/demo_cycle.py
python tests/test_forecast.py
```

## 六、三条必须说清楚的话

1. **这里的数字来自合成市场。** 隐藏阶段是我定义的，所以"61.5% 的一致率"
   证明的是"规则能捞回一个已知的周期"，不是"A 股存在这样的周期"。
   真实历史需要你自己接上 `evaluate()` 跑一遍。

2. **55% 不是这份代码的失败，是所有手写预测规则的常态。**
   区别只在于：大多数模块不会告诉你这个数字。

3. **仓位上限不是收益率。** 它是一句经验："高潮别满仓"。真正赚钱与否，
   取决于你在每个阶段买了什么——那是另一个问题。

那个记分牌最值钱的地方，是它让你可以诚实地回答一个问题：

> **你的预判，比"什么都不做"强多少？**

如果答案是"不强"，至少你现在知道了。
